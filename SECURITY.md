# Security Policy

## Supported Versions

We are currently providing security updates for the following versions of the Credit Card Fraud Detection Model:

| Version | Supported          |
| ------- | ------------------ |
| 1.0.x   | :white_check_mark: |
| < 1.0   | :x:                |

## Reporting a Vulnerability

Security is a top priority for this project. If you discover a potential security vulnerability (such as data leakage risks, insecure dependencies, or API exposure), please do **not** open a public issue. Instead, follow these steps:

1. **Email directly:** Send a detailed report to **tufaquesayyed@gmail.com**.
2. **Details to include:**
   - A description of the vulnerability.
   - Steps to reproduce the issue.
   - Potential impact of the vulnerability.
3. **Response Time:** We aim to acknowledge all reports within 48 hours and provide a fix or mitigation plan within 7 days.

## Model & Data Security
* **Adversarial Attacks:** We encourage reports regarding model bypass techniques or adversarial examples that could deceive the fraud detection logic.
* **Data Privacy:** As this project involves Credit Card transaction data, please ensure that any datasets used for testing are fully anonymized. Never commit raw CSV files containing real personal identifiable information (PII) to this repository.

## Responsible Disclosure

We ask that you give us reasonable time to investigate and mitigate the issue before making any information public. We appreciate your help in keeping this project and its users safe.
